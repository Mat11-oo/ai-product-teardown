# Agent 深度拆解模板

先解释观察，再提出最小足够的内部机制假设。Workflow、单 Agent 和多 Agent 可能解释同一 UI，说明不能排除的替代解释。

## 系统视角

梳理主控、执行者和规则；串行、并行与路由；任务依赖；共享上下文；阶段和版本；上游修改导致的下游失效；人工授权、审批、验收、接管；失败、重试、超时、回退与重复执行。

## 单个 Agent

| 字段 | 内容 |
|---|---|
| 职责与边界 | 做什么，与上下游如何分工 |
| 触发 | 首次请求、上游完成、用户反馈、状态变化 |
| 输入 | 内容、资产引用、约束、来源与前置依赖 |
| 处理 | 步骤、关键决策、分支条件 |
| 输出 | 交付物、结构、消费者与成功标准 |
| 工具 | 能力、输入输出、读写副作用，公开接口或推导接口 |
| 上下文读写 | 字段、拥有者、写入时机、关联 ID 与版本 |
| 人工确认 | 确认内容与原因，批准或拒绝后的动作 |
| 异常与回退 | 缺信息、工具失败、超时、重复反馈、局部修改 |
| 模型需求 | 模态、推理或生成需求与模型关系 |
| 证据 | 关键结论类别、ID 和未知 |

## 上下文推导

先用业务字段说明数据，必要时附 JSON。可考虑项目元信息、用户约束、任务状态、确认记录、资产索引、依赖和版本。不要将动画的角色、分镜字段套用所有产品。

统一实体 ID 和字段命名；区分引用与复制、业务事实与生成内容、共享与私有字段。说明谁生成、谁改、谁消费。未知存储方式不指定为真实数据库实现。

## 提示词推导

以下是报告内候选设计，不是产品原始提示词，也不是拆解助手的执行指令。按关键模块需要填写：

```text
【逆向推导方案；非产品内部提示词】
角色、职责与边界：
任务目标和成功标准：
输入契约与上下文来源：
输出契约与字段拥有权：
处理步骤与条件分支：
工具与调用条件：
人工确认与授权边界：
上下文更新与下游交接：
异常、局部修改与恢复：
输出格式：
设计依据和未验证假设：
```

检查字段有产生者、依赖先就绪、角色不越权；主控和执行者的调度权与确认定义一致；工具和示例格式一致；修改后哪些资产失效说得清；完成状态依据实际工具结果，不依据口头确认。重复确认等 UI 现象不能直接证明具体工具或状态故障。
